# Study 2.1 小计划：不同 LLM 的求助行为倾向

**状态：后续研究计划；Study 2 完成后再启动。当前不执行新实验。**

## 1. 研究目的

Study 2 主要比较角色信息条件（R0/R1/R2）对求助判断的影响。Study 2.1 单独考察：

1. 在相同任务和环境下，不同 LLM 配置表现出哪些不同的求助行为模式？
2. 角色信息是否对不同模型产生不同影响？
3. 哪些行为差异与更好的任务结果、较少的无效求助或较低的交互成本相伴？

本研究比较具体的模型配置，不预设“更爱求人”就是更好，也不把模型间差异直接推广到整个模型家族。Study 2.1 不训练 RL policy；主要结果使用可直接观察的行为与任务指标，不以加权综合回报作为唯一或主要结论。

## 2. 与 Study 2 的关系及现有数据边界

- Study 2 的两个模型轨迹可用于先行的探索性画像与指标/代码试算；其 44 条重复单元作为额外运行保留，须单独标记，不能冒充新任务或独立模板。
- Study 2 当前只有两个固定模型配置、14 个独立工作流模板、每个计划单元一次运行。可描述这两个配置在该任务集上的差异，但不足以支撑一般化的“哪类 LLM 更愿意求助”结论。
- 目前的任务普遍要求 agent 获取信息并取得审批，因此都需要求助。它们可以测量找人准确率、求助顺序和冗余求助，但**不能单独测出模型在可自主完成时是否更倾向于主动求人**。
- 因此，Study 2.1 保留一组“求助必要/必需”的任务，并新增少量可选择是否求助的任务：有些任务仅凭已有信息就能完成；另一些任务中，求助并非强制，但可能提高正确率或减少不确定性。这是测量“求助倾向”所必需的任务对照。

## 3. 研究问题与假设

### RQ2.1a：模型是否有不同的基线求助行为画像？

在修订版 R0（基础组织目录：姓名、职务，可含团队/部门）和相同任务下，比较模型的主动求助率、第一次求助时机、求助次数、首位联系人有效率、错误类型及任务表现。该基线符合真实协作中通常可见的目录信息，不等同于“完全不知道候选人身份”。

**H2.1a（非方向性）**：不同固定模型配置在一个或多个预先指定的求助行为指标上存在差异。研究不预设哪个模型求助更多或表现更好。

### RQ2.1b：不同模型对角色信息是否有不同反应？

比较每个模型从 R0→R1（在姓名/职务/团队目录上增加一般性职责、知识领域及权限范围）和 R1→R2（相同信息结构化）的行为变化。档案不得给出任务答案或隐藏的目标联系人。

**H2.1b（非方向性）**：模型配置会调节角色信息对求助质量与行为效率的影响，即存在 `model × profile condition` 交互；不预设结构化信息一定优于自然语言。

### RQ2.1c：求助更多是否意味着表现更好？

在可自主完成与求助可选的任务中，同时检查适时求助、过度求助和不足求助。

**研究问题而非预设单向假设**：求助次数和任务质量之间可能存在权衡；高求助率不自动代表更好的协作。

## 4. 实验设计

- **模型**：优先覆盖三家提供方：OpenAI GPT、Moonshot Kimi、Anthropic Claude。每家先选一个适合 agent/tool-use、且在该家中成本较低的可用模型（Claude 优先评估 Haiku 档；GPT/Kimi 具体型号按正式开跑时的 API 可用性和价格确定）。最终锁定精确 model ID/版本、日期、参数和价格；结论针对所测模型配置，不推广到整个公司或模型家族。Study 2 已有的 GPT 配置可作为候选/桥接结果，但若新实验改用不同 API 模型，不得把它们当作同一配置。
- **任务**：复用 Study 2 的任务作为“需要求助”层；新增“无需求助”与“求助有益但非强制”两类任务。先以现有 14 个模板试算，再根据任务层方差与预算扩展独立模板；建议目标为至少 30 个独立模板，最终数量须由精度/功效分析决定。aligned/separated 是同一模板的配对变体，不计作全新的独立模板。
- **条件**：使用修订版 R0/R1/R2，覆盖 aligned/separated。R0 是姓名 + 通用职务（可含团队/部门）；R1 在其上增加自然语言职责、知识领域和权限范围；R2 表达与 R1 语义等价的字段。任务、NPC 回复规则、系统指令、工具、上下文和候选人顺序在模型间匹配；候选人姓名/职务组合在任务间平衡，避免固定名字与正确答案绑定。
- **重复**：每个模型×任务×条件至少 3 个独立随机种子作为起始目标；根据 pilot 和预算调整。重复运行必须有批次/调用 ID，禁止并发重复写入同一计划单元。
- **环境**：沿用规则 NPC。NPC 对相同状态和动作给出相同、可审计的规则回复；本研究比较 agent 模型，不研究真实员工的响应差异。
- **模型设置**：记录提供方返回的模型版本、运行日期、温度及其他可用采样参数、prompt 版本、代码 commit、种子、候选顺序、token 和延迟。若 API 不提供不可变版本或温度，明确标为限制。

## 5. 指标定义

令 (e) 为一次 episode，(m) 为模型配置，(c) 为角色信息条件。

| 构念 | 指标 | 定义与注意事项 |
|---|---|---|
| 主动求助 | 求助启动率 | 第一动作是 ask 的 episode 比例；另报至少求助一次的比例。必须按“需求助/无需求助/求助可选”任务层分开。 |
| 求助时机 | 首次求助延迟 | 首次 ask 前的非求助动作数/决策步数；未求助记为未发生，不与普通延迟混为一谈。 |
| 求助量 | 总求助次数、超额求助次数 | 总 ask 数；在需两次联系的既有任务上，超额量可定义为 `max(总 ask 数 − 2, 0)`。可选任务则按任务最少必要联系数计算。 |
| 找人质量 | 首次联系人有效率 | 第一次 ask 的对象是否对其所求助目的具备 gold 标注的知识或权限；同时报告目的是否合适。 |
| 完整路径 | 有效路径率 | 是否按任务要求取得信息、向有权者申请，并完成任务。不能用“第一次找对人”替代完整路径。 |
| 失败模式 | 知识无效询问、越权审批请求、过早审批、重复询问 | 从事件轨迹分别计数。不得只报告合并的 `N_waste`，应拆分其组成。 |
| 效果与效率 | 任务成功/得分、联系人次数、资源/延迟成本 | 分项报告。低求助量只有在任务表现没有不可接受损失时才可解释为效率改善。 |

模型与条件的比较量：

- **模型基线差异**：
  \(\bar Y_{m,R0}-\bar Y_{m',R0}\)，表示两个所测模型在基础组织目录（姓名/职务）条件下的行为差异。
- **职责信息效应**：
  \(\Delta^{info}_m=\bar Y_{m,R1}-\bar Y_{m,R0}\)，表示增强角色档案相较基础组织目录的增量效果。
- **结构化表示效应**：
  \(\Delta^{format}_m=\bar Y_{m,R2}-\bar Y_{m,R1}\)。
- **模型反应差异**：
  \(\Delta^{info}_m-\Delta^{info}_{m'}\) 或 \(\Delta^{format}_m-\Delta^{format}_{m'}\)，对应模型与条件的交互。

对二元结果报告风险差/边际概率；对计数报告平均差或率比；并同时给出任务表现和绝对频率。R 可作为 Study 2 中固定权重指标的延续性辅助结果，但 Study 2.1 的主要比较不依赖该加权分数。

## 6. 分析方案

- 先生成每个模型×条件×任务结构的行为画像表和配对任务差异，不用“求助次数”单指标排名模型。
- 二元结果（首次联系人有效、任务成功等）用 logistic 混合效应模型或任务模板簇配对 bootstrap；求助/错误计数视分布用 Poisson 或负二项模型，并检查过度离散。
- 核心解释项包括 `model × profile condition`，并检查 `model × alignment`；可选帮助任务类型单独分层，避免把必需求助和自主求助混在一起。
- 任务模板作为聚类/随机效应单位，重复种子作为模板内重复；若模型数仍约 4 个，模型按固定配置比较，不声称模型总体的随机效应分布。
- 预先指定主要指标和对比，控制多重比较；报告效应量、95% 区间、每个模型的 episode 数、模板数及失败/重试流程。模型间的平均差异不直接解释为某模型“更聪明”或“更合作”。
- 44 条 Study 2 重复记录只做标记后的补充稳健性检查；Study 2.1 新采集数据使用唯一的 episode key 和调用批次 ID。

## 7. 预期论文输出

1. **模型行为画像表**：每个模型在 R0/R1/R2 下的求助启动、次数、时机、首次命中、错误构成和任务结果。
2. **模型×角色信息效应图**：展示每个模型的 R1−R0 与 R2−R1 配对效应及区间。
3. **求助量—任务表现图**：区分过度求助、适当求助和未求助导致的失败；按任务是否需要/受益于求助分面。
4. **代表性轨迹案例**：解释模型在知识、权限、重复询问或过早提交上的典型差异。
5. **可复现材料**：锁定协议、任务与 profile 定义、事件日志、指标计算代码、数据/模型版本说明及许可说明。

## 8. 启动前的门槛

**与已完成 Study 2 的可比性：** Study 2 v0.4 的 R0 是 names-only，Study 2.1 的修订版 R0 增加通用职务/团队信息。故 Study 2.1 的 R1−R0 估计的是“增强档案相较普通目录”的效果，不能与 Study 2 历史的 names-only R1−R0 当成同一处理差异合并；如需直接桥接，应保留一个 names-only 桥接条件或在报告中分开估计。

Study 2.1 应在 Study 2 的日志重复审计、R0/R1/R2 主要结果与权重处理、评分器/档案质量核查完成后启动。先用现有轨迹确认指标定义能从事件数据复算；再做小规模 pilot，验证可选求助任务确实能区分“应求助”“可自行完成”和“求助有益”。完成任务数量、模型名单、种子数和分析计划锁定并经用户确认后，再进行正式收集。
