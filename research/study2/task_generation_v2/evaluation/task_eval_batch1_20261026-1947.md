## 3. Detailed findings

### F1 (o-low-campaign-asset) — cue is a hint; quality not measurable — REVISE
- `brief.md`: "Marketing maintains an optional campaign-specific asset that **improves visual alignment**; the evergreen asset remains valid." This tells the agent there is a better option, who has it, and that it is optional. §13.4 allows an *explicit* cue at Low level, but naming the improvement and the holder's function removes the decision we want to measure.
- Quality is `campaign_specific_asset: true/false`, a label rather than an outcome.
- **Fix:** make the cue a fact without evaluation, e.g., "Cedar launch creative was produced by the brand team in October; this brief predates it." Score quality by an observable outcome (e.g., asset metadata `campaign=Cedar` and `license_valid_through ≥ launch date`).

### F2 (m-high, m-medium) — the authority-holder is the top match by title
- In both Must tasks the approver (CTO, Finance Director) is the highest word-overlap candidate even in R0. This is partly realistic (approvals often go to obvious roles), but it means the "whom" difficulty in these tasks comes almost entirely from the **information** steps (Li Ming, Liu Qiang, Wang Fang) and from **order/context**, not from finding the approver.
- In m-high R1, the CTO addendum "Owns technical deployment mandates and cross-team production change windows" echoes `ownership.md` ("Executive technical mandates belong to the CTO") and the task prompt's "mandate_reference". Overlap 0.38 vs 0.19.
- **Fix (pick one per task):** (a) add a realistic conditional twist so the obvious approver is not always right (e.g., CTO on leave → delegate; or freeze overlap decides between project lead vs CTO, already present in m-high — make the no-overlap variant exist too); (b) soften the R1 addendum wording so it does not repeat the document phrase.

### F3 (m-medium) — difficulty features slightly inconsistent
- Separation scored 2 ("conditional": amount threshold) and inference scored 1. But identifying David Wong requires computing the current amount (20 × 600 = 12,000, which needs H1) and applying the threshold — the same conditional is counted in both features. Either score separation 1 + inference 2, or keep as is but document the rule ("conditional approval counts under separation only"). D stays 5 either way; this is a scoring-rule clarification for the generator.

### F4 (o-high) — check the baseline is truly valid
- The standard course (120 min, 16:00–18:00) overlaps the focused-work block by 60 min. `roster.md` says overlap is allowed but costs disruption, so the baseline is valid. ✅
- `cohort_sizes` as a list: equivalences should state order-insensitivity ([12,12] trivially fine, but say it).
- Holder inference needs two lookups (contract → PEOPLE group → HR custodian) and the Sales Director is a realistic decoy (Customer group). Good design.

### F5 (all tasks) — not yet verifiable statically
- **Release rules depend on LLM NPCs.** m-high requires Liu Qiang to withhold readiness unless the request has revision, 6 replicas, window and 20-minute rollback; Sarah Johnson must withhold the mandate without the readiness ID and freeze interval. These are exactly the order/context mechanics the paper relies on; they must be tested with the real NPC model before use (§14 B4/D1, and Redesign §11 D3).
- **No scorer yet** (`grading_implemented: false`). B1/B2 were judged from declared reference outputs; once the scorer exists, rerun the two references through it.
- **N vs visible accounts.** README notes all TAC accounts remain visible in RocketChat; N is the directory size. Fine, but the paper must define N as "directory size", and contacts outside the directory should be logged.

### F6 (positive) — design quality is high overall
- No hint words in any task.md; Must tasks all carry realistic stale/draft values (silent-failure traps); Optional tasks score real outcomes (cost, overlap minutes) except o-low; DAG and release rules make order and request context testable; R0/R1 share identical business documents.

## 4. Requests to the task generator
1. **o-low-campaign-asset:** rewrite cue as neutral fact; replace boolean quality with an outcome check (F1).
2. **m-high / m-medium:** reduce title/addendum overlap for the approver, or add a conditional so the obvious approver is not always correct (F2).
3. Clarify the scoring rule for conditional approval (separation vs inference) in the generation plan (F3).
4. Add order-insensitive equivalence for list fields (F4).
5. Before scaling to 60: implement the scorer and run both references through it; run a minimal NPC rule test for every gated release (missing context → refusal; full context → release) with the planned environment model.

## 5. Evaluator limitations
- Word-overlap is a coarse lexical proxy; it does not capture semantic matching by an LLM agent.
- Realism (D1/D2) not assessed; recommend one human pass on the 6 tasks before generating the remaining 54.
