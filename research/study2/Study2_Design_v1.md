# Study 2: Role-Aware Help-Seeking — 实验设计 v1

**状态：Study 2 实验与分析收尾已完成。** 历史运行、数据质量审计、规则评测器边界测试及 profile 信息匹配的 v0.4 确认性复核均已完成。详细执行协议与结果见 [`confirmatory_extension_protocol_v0.2.md`](confirmatory_extension_protocol_v0.2.md) 和 [`derived/study2_v04_analysis.md`](derived/study2_v04_analysis.md)。历史数据不删除；历史 R1/R2 对比因信息内容不等价，不作为格式效应证据。用户决定不做 R 权重敏感性分析。

## 0. Study 2 最终要回答什么

Study 2 是一个受控实验，研究 agent 已经需要求助时，能否利用团队成员的信息来选对人。Study 1 描述真实或公开轨迹中有哪些求助模式和错误；Study 2 对候选人信息的呈现方式做操纵，检验这些信息是否导致更好的选择，以及改善来自哪里。

**主问题：** 在任务和角色事实相同的情况下，向 agent 提供超出普通组织目录的增强角色信息，是否能改善有效求助路径与任务表现？这种作用是否取决于所需知识与审批权限由同一个人掌握，还是分散在不同人身上？把相同事实整理成结构化档案，是否又比自然语言职责描述更有帮助？

**条件版本说明：** 已完成的 Study 2 v0.4 按当时协议将 R0 定义为仅提供姓名/代号；该历史结果保持原定义，不追溯改名。后续更贴近现实的基线应定义为 **R0-basic directory：姓名 + 通用职务（可含团队/部门）**，不提供额外的任务相关知识领域、职责边界或明确审批权限；R1 在此基础上增加自然语言角色档案；R2 用结构化字段表达与 R1 语义等价的信息。因此，新设计中的 R1−R0 是“增强角色档案相较普通组织目录的增量效果”。Study 2.1 若采用新 R0，其结果须与旧版 names-only R0 分开报告，不能直接合并估计。

Study 2 允许 agent 在相同任务设置下自行决定何时求助、问谁，并完成一个或多个求助步骤。因此，当前实验估计的是端到端 help-seeking 行为，不是固定求助触发点下纯粹的 whom 选择。Study 2 主要检验角色信息条件及知识—权限配置；成本权重 λ、权限惩罚 μ 的系统扫描不纳入本研究。固定 R 仅作描述性综合指标，同时直接报告任务得分、成本及错误分项；不做 R 权重敏感性分析。

### Study 2 的预期贡献（研究目标，不是预设结论）

1. **因果证据：** 对不同角色信息表示做受控比较，估计职责信息、结构化表示分别对找人行为的影响。
2. **机制证据：** 用知识干扰项和权限干扰项区分“找到知道答案的人”与“找到有权处理此事的人”，并检验 agent 的错误究竟是哪一种。
3. **可复用评测材料：** 形成有明确有效求助对象集合、知识/权限真值、成本和可复现规则评分的任务集及逐步轨迹数据。

这三个是 Study 2 的目标；是否构成论文贡献取决于正式结果、任务质量和与已有工作的对比。

**目标函数在 Study 2 的作用：** Study 2 不训练/优化一个新策略；它用固定的 (R) 评价不同角色信息条件下现有模型的行为，并比较各条件相对 oracle 的回报差距。(T) 需按任务规则预先归一化；λ、μ、ν 在看正式结果前固定，并给出实际含义/量纲依据。主文同时报告 (T)、成本、权限错误、无效求助等分项，避免结论被任意权重主导。另做预先规定的合理权重范围敏感性分析；完整的 λ/μ 行为扫描及成本—成功率前沿属于 Study 3。

## 1. 实验设计总览

### 1.1 设计表

| 要素 | v1 方案 |
|---|---|
| 实验单位 | 一个任务 × 一个模型配置 × 一个随机种子的一次完整 episode |
| 主要随机化因素 | 候选人信息条件：R0、R1、R2；同一任务在各条件均运行 |
| 次级随机化因素 | 候选人集合难度/干扰项类型；成本显著性（基线 vs 明确成本提示，仅在预先选定子集运行） |
| 固定因素 | 任务事实、候选人身份/顺序（顺序另行平衡）、求助触发点、NPC 回答规则、工具与系统指令、模型解码参数 |
| 候选模型 | 先选 3–5 个稳定可调用的模型配置；模型是分层/分组因素，不把特定模型间差异解释为纯粹架构因果效应 |
| 求助路径 | 允许完成任务所需的一步或多步求助；每个任务预先标注有效路径集合 |
| 主要结果 | 有效求助路径完成率；固定权重下的综合回报 R 为共同主要/综合评估结果，并列报告所有分项 |
| 次要结果 | 任务完成/得分、首次接触有效性、知识有效性、审批有效性、越权、无效求助、成本、答复采纳 |

同一任务跨条件重复是配对设计。各条件使用相同任务蓝图，但随机化候选人显示顺序和非关键表面表述；固定或记录模型版本、prompt、温度、API 日期和失败重试。不能让某个条件独占更容易的任务或候选人顺序。

### 1.2 条件定义：角色信息 × 知识—权限配置（3×2）

- **历史 Study 2 v0.4 的 R0 — Name only：** 本轮已完成实验提供候选人姓名/代号，不提供职责、知识或权限描述。此为历史操作化。
- **后续修订基线 R0 — Basic directory：** 提供候选人姓名、通用职务，以及现实中通常可见的团队/部门信息；不额外列出任务相关知识领域、职责边界或明确审批权限。
- **R1 — Enriched natural-language role dossier：** 在 R0 基础上，以自然语言补充一般性职责、知识领域和权限/审批范围；不得泄露任务答案、具体 gold recipient 或隐藏情景事实。
- **R2 — Structured profile：** 用统一字段表提供与 R1 完全相同的语义事实，例如 `domain expertise`、`decision authority`、`availability`。R1 与 R2 的事实必须逐项一致；唯一主要差异是表示格式。

第二个操纵维度是知识与权限配置：**aligned** 表示至少一位候选人同时掌握所需信息且有权完成目标行动；**separated** 表示信息持有者和授权者不同，任务需要走通有效的多步求助路径（例如先向知情者获取事实，再向授权者申请批准）。对采用修订版 R0 的后续设计，核心设计为 3（R0/R1/R2）×2（aligned/separated）。修订版 R0 vs R1 估计增强档案相较普通目录的效果；R1 vs R2 估计相同信息结构化的增量效果；交互项检验知识—权限分离是否改变档案收益。R2 不得增加 R1 没有的事实或直接指出 gold recipient。

成本字段暂不混入主条件。如果研究成本敏感性，另设 **C0：不呈现成本** 与 **C1：呈现成本及明确的成本权衡规则**，在选定任务子集里交叉 R0/R1/R2 或仅在 R1/R2 上交叉。这样才能区分角色信息格式与“模型被提醒要省成本”的效果。若资源有限，先完成 R0/R1/R2 主实验，成本实验作为预注册的次级/后续实验。

### 1.3 任务与候选人构造

任务从 TheAgentCompany 的 NPC 场景获得真实感和角色素材，但需重新写成受控文本任务。不要把原任务指明求助对象的句子原样保留；也不要将受限许可下的原始内容直接作为新发布数据。建立版本化的任务蓝图，并记录来源、改写方式和许可核查。

每个任务须满足：

1. 存在清楚、可客观评分的任务目标与一个明确的求助触发点；agent 在该点前不能仅靠已给上下文可靠完成下一步。
2. 候选人数量和困难度合理；至少一个候选人可提供足够帮助。对于多个都可接受的情形，标注 **有效对象集合**，不人为规定唯一答案。
3. 分别记录候选人的相关知识和正式权限。知识匹配不能代替权限判断，权限也不能代替具体知识。
4. 任务包含可区分的候选人构型：
   - 有知识但无权批准/执行；
   - 有权批准但缺乏所需细节；
   - 知识部分匹配；
   - 知识和权限都满足但成本较高（若成本子实验纳入）；
   - 一个或多个真正有效的对象。
5. 设置难度对照：单一有效候选人、多个有效候选人、无明显干扰项、知识冲突项、权限冲突项。比较表示收益时，不能只依赖某一种干扰项。
6. 角色档案只能提供在真实组织中可合理知道的职责/知识范围，不直接泄露任务答案或标注的 gold recipient。

建议先制作 **约 40–60 个蓝图**作为起始开发目标，覆盖至少 3 个工作领域和上述候选人构型；最终任务数由 pilot 的任务间方差、失败率和功效分析确定，不把这个数量预先当成充分样本。任务分成开发/调试集与锁定测试集；正式结果以锁定测试集为主。

### 1.4 NPC 与环境控制

主实验使用文本模拟环境。NPC 的响应规则来自场景真值表：同一候选人对同一问题提供一致的事实；无权限者不会批准事项；不知道的人可以说明不知道，不能编造关键事实。可以用固定模板或由模型生成表面不同、但受真值约束的答复。首要结果直接由 agent 选中的对象与预先标注的 gold set 计算，避免用 LLM judge 判定“问对人”。任务完成也尽量由规则评测器判定。

每次对话记录完整输入、动作、回复、最终任务状态。规则评测器在主实验前用人工构造的边界案例验证；随机抽样人工审阅环境是否遵守知识/权限规则。NPC 脚本和 agent 被测模型分开配置，避免相同模型既产生选择又评判选择。

## 2. 假设与可证伪标准

以下为 confirmatory hypotheses。检验前需将最小有意义效应（SESOI）、置信区间/多重比较处理和模型具体版本写入分析计划；若样本规模不足以检测预期效应，则将相应分析标记为探索性。

### H2a：职责信息有助于选人

**后续修订设计的 H2a：若** agent 获得与任务语义一致的增强角色档案（R1），**则**首次选择有效求助对象的概率高于只提供姓名、通用职务和团队信息的基础目录（R0），**因为**额外的知识领域和权限边界能缩小其对“谁可能知道/能做”的不确定性。已完成 v0.4 的历史检验仍对应 names-only R0，不能冒充检验了此修订假设。

- 后续修订设计的主比较：R1 − R0，结果为首次有效对象选择率；R0 指基础组织目录。
- H0：R1 与 R0 的有效选择率无差异。
- 不支持条件：预注册置信区间排除了有意义的正效应；或效果只出现在某个模型/任务子集且总体估计不稳健。

### H2b：结构化表示可能进一步改善选择

**若**把与 R1 完全相同的角色事实改为统一字段（R2），**则**在候选人信息需要跨多个维度整合时（特别是知识与权限可能冲突），R2 的有效选择率高于 R1，**因为**字段化可能降低比较不同候选人时的遗漏和混淆。

- 主比较：R2 − R1；并预先指定 `profile condition × conflict type` 交互为机制检验。
- H0：R2 与 R1 没有差异；或结构化格式不特异地改善冲突任务。
- 关键公平性约束：R1 与 R2 的信息事实和字数差异尽量控制/记录；做长度敏感性检查。结论应表述为“在本研究操纵下的表示效果”，不要泛化成所有结构化档案都更好。

### H2c：知识—权限分离会改变角色信息的收益

**若**任务所需知识和权限分散在不同的人身上，**则**agent 必须整合角色信息并完成多步路径；因此角色信息对有效路径完成和综合回报的改善可能在 separated 条件下更明显。

- 检验：`profile condition × alignment` 交互；报告两种配置中的有效路径完成率、综合回报边际效应及区间。
- H0：没有可辨别的交互，或角色信息收益在 aligned 与 separated 条件相当。

### H2d：角色信息分别改善知识匹配与权限判断

档案提供候选人的知识领域和权限边界后，相较 R0，R1/R2 可能减少知识错误与权限错误。两个结果必须分开报告，避免合成指标掩盖错误来源。权限错误按行为后果定义：询问某人是否知道规则不自动算越权；要求无权者批准、获得受限信息或代为执行才计为权限错误。

### H2e（次级/可选）：显式成本能否使选择更节省打扰

仅当成本子实验获批并纳入 Study 2：**若**提供一致的成本信息和明确权衡准则，**则**agent 会更多选择低成本且仍属有效集合的对象，降低成本而不造成实质性任务成功损失。

- 比较 C1 vs C0；同时看是否保留有效路径与任务表现。
- 报告任务成功与求助成本的联合结果/帕累托前沿，以及相对预先计算的 oracle 的 regret。
- 该子实验只能回答给定求助机会下的成本选择，不单独证明模型学会了减少求助；求助次数变化需由任务本身提供可选求助/自主完成的决策点。

**推荐的范围决策：** 主 Study 2 包含 H2a–H2d。H2e 单列为 optional module；不将 H3 的 λ/μ 大规模扫描并入 Study 2。

## 3. 输出指标与预注册分析

### 3.1 主要和次要指标

| 指标 | 操作定义 | 地位 |
|---|---|---|
| 有效求助路径完成率 | 是否通过一条 gold valid path 取得必需信息并完成必要授权；路径可包含一个或多个求助事件 | **主要结果** |
| 综合回报 R | `T − λΣc − μN_auth − νN_waste`，使用预注册固定权重 | **主要综合结果；须与各组成项并列报告** |
| 首次有效接触率 | 第一次求助对象是否属于当前状态下能推进 gold path 的对象集合 | 次要过程结果 |
| 知识有效率 | 被问对象是否具备回答当前问题所需知识；按任务 gold 规则判断 | 次要、机制指标 |
| 权限有效率 | agent 是否把需授权的请求交给有相应权限的对象 | 次要、机制/安全指标 |
| 无效求助率 | 对象既不能提供必要信息，也无法授权；重复/无关询问另编码 | 次要 |
| 任务完成率/规则得分 | 终局答案字段或检查点通过率 | 次要，受NPC与任务设计共同影响 |
| 答复采纳率 | 对有效答复作出正确后续行动的比例 | 次要，体现求助后是否用上信息 |
| 求助成本 | 如成本模块开启，按预注册成本表累计 | 可选次要 |
| 解析/调用失败 | 输出不符合协议、API错误、环境错误分别记录 | 质量控制，不默认为行为失败 |

### 3.2 统计模型

- 有效路径完成率为二元结果。建议用混合效应 logistic 回归：`valid_path ~ profile_condition * alignment + model + (1 | task)`；报告边际概率、风险差及 95% CI。
- 综合回报 R 按其经验分布选择适配的混合模型；报告固定权重下条件差异和区间，并用各分项解释 R 的来源。
- 预设对比：R1 vs R0（信息效应）、R2 vs R1（表示效应）、`profile_condition × alignment`（知识—权限配置交互）。主要对比的多重检验处理须预注册。
- 知识错误、权限错误分别用二元混合效应模型；任务得分用适配其分布的模型（如二项模型或有界连续模型），不得只因结果方便就选普通线性回归。
- 同任务的不同条件是配对数据。随机种子是重复测量，不得把重复运行当作完全独立任务扩大有效样本量。
- 检验模型配置异质性：先报告总体平均条件效应，再报告条件×模型交互作为异质性分析，不把某一个最好模型的结果代表所有 LLM agent。
- 试跑后基于任务层方差、基线命中率和最小有意义效应，做模拟功效/精度分析，决定任务数、每格重复数和模型数。设定固定的停止规则；不根据中途 p 值继续追加样本。

### 3.3 关键控制和稳健性分析

1. **语义等价检查：** 让独立标注者核查 R1/R2 是否包含相同事实，且没有暗示 gold recipient。
2. **候选顺序：** 平衡随机排序；报告首位/末位偏差。
3. **长度与措辞：** 控制或记录 profile token 数；复跑长度匹配子集。
4. **重复性：** 不同随机种子与候选人名字替换；报告模型版本/日期。
5. **有效集合：** 用 oracle/gold set 评估多答案情境；给出对“唯一最优对象”子集的敏感性分析。
6. **任务依赖：** 留出任务集作主要评估；探索性地留出角色组合/组织布局评估迁移，但不把有限样本下的外推说成普遍泛化。
7. **错误审计：** 人工盲审随机抽取的轨迹及所有权限错误候选案例，核验规则标签、对话协议与 NPC 忠实度。

## 4. 论文中 Study 2 的呈现方式

### 4.1 建议章节结构

1. **Study 2 Overview / Research Questions**：解释 Study 1 的观察如何导出“角色信息是否能改善找人”的因果问题；明确本实验固定求助时机。
2. **Task and Environment**：任务蓝图来源、场景构造、候选人类型、知识/权限真值、有效对象集合、NPC 响应规则。
3. **Conditions and Procedure**：R0/R1/R2 信息操纵、成本模块（如有）、随机化、模型配置、种子和每局流程。
4. **Measures and Gold Labels**：主指标、知识/权限错误、任务得分、成本、规则评测器与人工验证。
5. **Analysis Plan**：单位、混合效应模型、预注册比较、多重检验、功效/精度设计。
6. **Results**：先主结果，再干扰类型/知识和权限机制，再任务完成/成本，最后稳健性及模型异质性。
7. **Discussion and Limits**：模拟环境、档案质量、单次求助、跨组织外推以及与 Study 1 的互补关系。

### 4.3 结果文字模板（不预填答案）

按假设逐段写：**问题 → 操纵/比较 → 观测结果与不确定性 → 结论边界**。例如：“为检验职责信息是否改善有效求助，我们比较 R1 与 R0 的路径完成率和固定权重下的 R……。模型估计差异为……（95% CI……）。该结果[支持/不支持/证据不足以判断] H2a。该效应在……任务中更强/未见明确差异；因此它说明……，但不能说明……。” 不根据方向性点估计把未显著或宽区间结果写成肯定结论。

## 6. Step-by-step 执行框架（审批后按序推进）

### 阶段 A：锁定研究范围与协议

1. 明确 Study 2 主实验范围：固定求助机会/触发规则，保留多步路径；确认成本子实验是否纳入本轮。
2. 锁定 H2a–H2d 的主/次结果、有效路径定义、候选冲突类型、排除规则和统计对比。
3. 写 `protocol.yaml`，记录模型与服务版本、随机化、重试规则、任务 split、功效/精度分析方式和停止规则。
4. 单独做资料来源及许可核对；决定 TAC 衍生任务是否只内部使用、公开改写版，或完全自编。

### 阶段 B：建任务和 profile 语料

5. 从 TAC 场景抽取适合的任务骨架，另写合成/改写蓝图；确保不能只靠任务文本直接猜出目标对象。
6. 给每任务制作候选人真值表：知识、权限、可接受帮助、成本（如适用）、不能做什么。
7. 生成 R0/R1/R2 视图；用双人或独立审阅检查 R1/R2 的事实等价、可读性、泄漏答案情况。
8. 盲审有效对象集合和冲突类型；分歧裁决后锁定 gold 标签。
9. 按任务蓝图分成开发集与锁定测试集；不以测试结果回改任务/提示后仍称其为同一个锁定测试集。

### 阶段 C：环境、评测器和小规模验证

10. 搭建可执行多步路径的文本环境与 NPC 规则响应器；同一状态在相同动作下得到一致的事实答复。
11. 写规则评分器，覆盖有效对象、权限错误、知识错误、任务完成、空输出、重复动作和环境错误。
12. 写 evaluator 单元/边界案例；让人工逐项核对预期标签。特别检查“询问权限”与“要求无权者批准”的区别。
13. 在开发集做小规模 pilot，检查协议解析率、零方差/天花板、候选顺序偏差、NPC 脚本违规和调用成本；pilot 数据不纳入正式确认性检验，除非事前定义为可合并的内部 pilot。
14. 根据 pilot 估计任务层方差和基准命中率，模拟样本量与区间精度；确定运行数及预算。不得用 pilot 的显著性筛选假设。

### 阶段 D：正式数据收集

15. 冻结任务、档案、prompt、工具、模型版本、评测器和代码 commit；生成 manifest/hash。
16. 对每个锁定任务执行所有 R0/R1/R2 条件；随机平衡候选人次序和 seeds。成本条件仅按已锁定子实验运行。
17. 保存全部逐事件轨迹、API 参数、错误和重试，不静默重跑/剔除失败局。
18. 依据预注册规则区分模型行为失败、协议失败、API/基础设施失败。报告各类失效率；基础设施失败按预注册方案重跑并保留原记录。

### 阶段 E：质量审计与分析

19. 运行自动校验：gold 完整性、候选人映射、事件顺序、重算分数一致性、重复 run、随机化平衡、环境规则遵循。
20. 盲抽轨迹供人工检查，包含全部权限错误及一定比例普通轨迹；分歧裁决，记录一致性与错误修订。
21. 先在锁定数据上生成样本流图和排除明细，再跑预注册主模型；保留运行级数据和模型估计。
22. 做稳健性和异质性分析；明确标识 exploratory，不能把探索结果写成事先假设。
23. 生成图表、结果摘要和可复现脚本；以 `task_id/run_id` 将每项主结果追溯到 gold 与原始事件。

### 阶段 F：论文撰写与复现包

24. 按 §4 的 Study 2 结构撰写；逐项把 H2a–H2d 映射到比较、指标、图表、结果和限制。
25. 形成数据卡/任务说明、模型运行说明、评分器说明和许可声明；根据许可和隐私决定公开级别。
26. 由独立审阅者从干净环境复跑汇总表与主图，检查图表数字和文中数字完全一致。

## 7. 停止/返工判据与风险

开始正式采集前必须通过：

- R1/R2 语义等价审计无实质差异；档案没有直接泄漏 gold 目标。
- 规则评测器的边界案例通过人工核对；关键结果不依赖 LLM judge。
- Pilot 没有无法解释的天花板/地板、严重解析失败或明显候选顺序偏差；若有，先修订任务或协议并重新冻结。
- 样本量/精度计划能覆盖预设的最小有意义效应，预算与调用额度可行。
- 所有任务来源、派生和可发布范围已记录。

主要风险：模拟任务和 NPC 不能代表真实组织；profile 事实可能过强或过弱；不同模型 prompt 能力和 API 版本带来配置差异；固定单次求助不能说明多轮时机策略；若档案与候选顺序泄漏答案，会夸大效果；TheAgentCompany 改写/衍生内容仍需许可审查。论文应把结果限定为“在受控文本任务与本次候选档案操纵下”的因果证据。

## 8. 审批后执行顺序

用户批准本设计后，按阶段 A→F 自主执行；遇到会改变核心研究问题或样本来源合法性的选择，再汇报并解决后继续。首个执行里程碑不是大规模跑模型，而是交付锁定协议草案、任务蓝图样例、profile 等价审计和 evaluator 边界测试。通过这些质量门后再开始正式试验。
