## 0. 旧控制器 SFT87 的独立验证结论（背景）

- 16 dev 题：内容通过率不变（0.312 vs 0.312）；完整交付 0.25 → 0（配对差 −0.25，95% CI [−0.50, −0.06]）；T −0.016；R −0.006。
- SFT87 在 124/124 个决策都选 NO_ASK；4 道有 trace 的题中，gold 要求问的决策 ASK 召回 0/32；即使强制问，最高分候选人只在 2/4 题是正确持有人。
- 结论：不建议修补 SFT87，按 v1 重新设计。

## 1. 四个 arm：定义

2×2 拆开控制器的两部分能力，**都不需要训练**：

| | 请求内容（what）由执行器写 | 请求内容由规则补全 |
|---|---|---|
| **when + whom 由执行器决定** | **A 原生** | **C 原生 + 规则补全** |
| **when + whom 由 oracle 决定** | **B oracle** | **D oracle + 规则补全** |

- **A**：GPT-5.4-mini 自己决定问不问、问谁、怎么写（=论文设置，基线）。
- **B**：oracle 决定何时问 / 问谁，mini 自己写请求。
- **C**：mini 决定何时问 / 问谁；发 ASK 时系统自动附上已获得的相关值。
- **D**：两者都用，当前执行器的总上限。

## 2. 四个 arm：做法

1. **Oracle 控制器**（规则代码，读 `gold/blueprint.json`，只用于测上限，不能作为方法）：每个决策点
   - 存在"前置已满足、本步未满足"的步骤 → ASK 该步骤最便宜的 admissible 联系人；
   - 所有步骤已满足 → SUBMIT；
   - 否则 → SELF（执行器做一步普通操作）。
2. **规则补全**（只用公开对话历史，不读 gold，是合法方法）：从已收到的回复中抽取值（编号、金额、ID 等），在 ASK 时附进请求；执行器只能改写措辞，不得删掉附加的值。
3. **运行条件**：四个 arm 同一执行器（gpt-5.4-mini）、同一 LLM NPC、同样 60 题、每 arm 3 次；用 TribalBench scorer（`tribalbench-1.0`）计算 R 及分量（T、excess C、N_auth、N_waste）。
4. **读法**：B−A = 完美 when/whom 的上限；C−A = 只补 what 的收益；D−A = 总上限。**门槛**：(B−A) 或 (D−A) 平均 R ≥ 0.10 才进入训练；否则瓶颈在执行器，先改进请求写法与被拒补救。
5. 报告时 must-help 与 optional-help **分开**报。

## 3. 假设（推断，待 Phase 0 验证）

| ID | 假设 | 依据（论文数据） |
|---|---|---|
| H1 | must-help 上 B−A 很大，提升主要来自"逼 mini 去问"，而非"问对人" | mini must-help 只问 3/30；不问 0/41 完成，问了 69/79 完成；首次联系正确 79/79 |
| H2 | C−A 很小 | 规则补全只在 ASK 时生效，而 mini 很少问 |
| H3 | D−B > 0 | 问了的 79 次中 41 次被拒，多因请求缺少前一步的值 |
| H4 | optional-help 上 B−A ≈ 0 甚至 < 0 | 问只带来质量提升却付打扰成本；Kimi optional 问了 R=0.20 < 不问 0.46 |
| H5 | 门槛会通过，但主要因为 mini 不愿问；换 GPT-5.4（must 问 25/30）为执行器时 B−A 小很多 | 两模型提问倾向差异 |

**推翻条件**：
- B−A < 0.10 → 被逼去问也写不好 / 处理不了拒绝，瓶颈在执行器。
- C−A ≥ D−B → what 比 when/whom 更重要，研究重心转向 what。
- optional 上 B−A 明显为正 → 打扰成本权重偏低。

## 4. 若假设成立：训练方案调整（相对 v1）

| 假设成立说明 | 调整 |
|---|---|
| H1：价值在 when | when 头为核心：样本最多、loss 权重最大 |
| H1：whom 容易 | whom 只做监督学习，不单独优化 |
| H2/H3：what 只在问了之后起作用 | 先用规则补全代替 what 头；有余力再学 |
| H4：optional 不该一律问 | 用 RL 按 R 学"值不值得问"（监督标签教不会） |
| H5：执行器越弱帮助越大 | 训练/评测轮换 mini 与 GPT-5.4 作为执行器 |

### 步骤

1. **环境（本地，0 API）**：程序化生成组织与任务（TribalBench blueprint 格式）；规则 NPC（带齐 required_context 且前置满足才释放，否则拒绝并说明缺什么）；按组织划分 train/dev/test，测试组织训练中完全不可见。
2. **监督预训练（when + whom）**：
   - 标签来自 gold DAG：when = ASK / SUBMIT / SELF（同 oracle 规则）；whom = 合格联系人，按公开职责描述打分，**不输出人名**。
   - 数据 = oracle 轨迹 + **扰动轨迹**（找错人、漏步骤、请求缺值，再由 oracle 补救）。
   - 类别加权，防止学成"永远不问"；先做 200 状态过拟合 sanity。
   - 门槛：ASK 召回高（报 P/R/F1），whom top-1 ≥ 0.85。
3. **强化学习（值不值得问）**：从第 2 步初始化，GRPO（组大小 8，KL β=0.02），奖励 = R，无额外 shaping；70% must / 30% optional。目标：optional 上提升不够就不问、被拒后补值重试、减少冗余联系。门槛：Dev-new-org 上 R 显著高于第 2 步（配对 bootstrap CI 不含 0），N_auth 不增加。
4. **评测（冻结后只跑一次）**：未见组织 + TribalBench 60 题，每题 3 次。对照：原生 mini / GPT-5.4、提示词控制器、只学 when、when+whom、oracle。主要看 mini+控制器 能否拿到 oracle 提升的大部分，且在 GPT-5.4 上不变差。
