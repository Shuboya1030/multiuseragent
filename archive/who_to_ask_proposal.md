# Role-Aware Help-Seeking：研究方案 v0.1

> 依据：`who_to_ask_survey.md`（文献核查），以及 ReHAC（Feng et al., Findings EMNLP 2024）的贡献结构。
> 本文是研究设计，**不是已有结论**。标"估计"的数字是粗略预估，需要做小规模试跑来校准。

## 0. 一句话问题
多人共用一个企业 agent 时，agent 卡住了，**应该在什么时候、去找哪个人**？每个人的知识、权限、打扰成本都不一样。目标是：任务成功率尽量高，打扰成本和越权风险尽量低。

## 1. 三个贡献（对照 ReHAC）

| | ReHAC | 本研究 |
|---|---|---|
| C1 方法框架 | MDP；动作是"人 或 agent"；奖励 = 任务得分 − λ·人工介入次数 | MDP；动作是"agent 自己做 或 问人₁…人ₙ"；每个人有**角色档案**；奖励同时包含**按人计价的打扰成本**和**越权惩罚** |
| C2 训练模型 | Llama-2-7B + LoRA，离线 REINFORCE | 7–8B 开源模型 + LoRA，离线 RL，输出"是否求助 + 找谁" |
| C3 对比分析 | 基线：只用 agent、只用人、随机、Prompt、IL | **多个 LLM 直接当路由器** × **角色信息条件** × **成本权重扫描** |

### C1 方法框架：when + whom 联合建模
- **状态** sₜ：任务描述、到目前为止的轨迹、候选人列表及其角色档案。
- **动作** aₜ ∈ {SELF} ∪ {ASK(hᵢ, q) | i = 1..n}，即 agent 自己做这一步，或者带着问题 q 去问某个人 hᵢ。
- **角色档案** Pᵢ = ⟨知识域 Kᵢ，权限 Aᵢ，打扰成本 cᵢ，可用性 vᵢ，可信度 ρᵢ⟩。前两项决定"问他有没有用"，后三项决定"问他值不值"。
- **奖励**：

$$R = T \;-\; \lambda \sum_t c_{h_t} \;-\; \mu \cdot N_{\text{越权}} \;-\; \nu \cdot N_{\text{问错人}}$$

  - T：任务得分，沿用 TheAgentCompany 的检查点得分。
  - λ：打扰成本的权重（对应 ReHAC 的 λ）。
  - μ：越权惩罚。例如去找没有审批权限的人批预算，或者把信息透露给不该知道的人。
  - ν：问错人的惩罚，即对方没有所需知识，造成一轮无效询问。
- **框架层面要说清楚的设计选择**（论文里的 design space）：
  - 角色档案用自然语言写，还是结构化表示？
  - 档案是给定的，还是从交互历史中学出来的？
  - when 和 whom 是两阶段先后决策，还是一个策略同时决定？

### C2 训练模型
- **策略模型**：Qwen2.5-7B 或 Llama-3.1-8B + LoRA。不选 Llama-2，是因为它太旧，审稿人会问。
- **数据收集**：仿照 ReHAC 的"随机分配"。每一步按一定概率让 agent 自己做，或者随机问某个人，记录最终得分和成本。人由 LLM 扮演，NPC 的 profile 和私有信息来自 TheAgentCompany。
- **训练**：离线 REINFORCE 或 GRPO，优势函数用同一状态下的平均回报做基线。
- **对照**：再训练一个只决定 when、whom 交给 prompt 的模型，用来检验"联合决策是否更好"。
- **算力（估计）**：7B 模型 + QLoRA 用单卡 24–48GB 就能训练。主要开销在**收集轨迹时调用 API**。按每条轨迹十几轮调用、几千条轨迹算，大约在几百美元量级（估计，需要试跑校准）。

### C3 对比分析（具体化你说的"按什么权重比较"）
三个维度交叉：

1. **不同 LLM 直接当路由器（零样本）**：GPT-4o / GPT-4.1、Claude Sonnet、Gemini，以及开源的 Qwen 和 Llama。问题是：**哪些模型天然更会找人？**
2. **角色信息条件**：
   - R0：只给名字
   - R1：给自然语言职责描述，即 TheAgentCompany 现有的 `public_info`
   - R2：给结构化角色档案（知识、权限、成本）
   
   问题是：**显式的角色模型带来多少提升？**
3. **成本权重扫描**：
   - λ 从小到大：打扰便宜 → 打扰昂贵
   - μ：越权零容忍 → 宽松
   - 让 cᵢ 随职级变化，比如问 CTO 的成本 > 问工程师
   
   问题是：**模型的找人行为会不会随成本合理调整？** 输出成本–成功率的帕累托曲线。

**指标**：
- 任务成功率
- 首次求助命中率（第一次就问对人）
- 总打扰成本
- 越权次数
- 无效询问次数
- 该问没问的比例

## 2. 环境：WhoBench（暂定名），基于 TheAgentCompany 扩展
- **底座**：TheAgentCompany 中有 17 个人类角色（`npc_definition.json`）。有 41 个任务带 `scenarios.json`，规定了哪个人持有哪条信息。
- **需要扩展的地方**：给每个任务加入**干扰候选人**：
  - 知情但**没有权限**的人
  - 有权限但**不知情**的人
  - 两者都具备、但**打扰成本很高**的人（比如 CTO）
  - 只知道**部分信息**的人
- **轻量化实现（建议）**：不跑完整的 Docker 环境（GitLab、Plane、ownCloud 等），只抽出"找人"这部分，做成**纯文本模拟器**：NPC 由 LLM 扮演，任务结果由规则评测器判定。这样成本和工程量都会大幅下降。代价是生态有效性变弱，需要在论文里说明。
- **规模目标（估计）**：100–200 个任务。可以手工改写 41 个现有任务，再用 EnterpriseBench 的组织元数据生成管线补充。

## 3. 实证诊断（"实证 + 设计框架"中的实证部分，也是论文的动机证据）
- 在 TheAgentCompany 已公开的约 1.9k 条轨迹中，选出涉及 NPC 交互的任务，标注每一次求助：
  - 问对人
  - 问错人
  - 该问没问
  - 问了但没有跟进（TheAgentCompany 论文自己也报告过这类失败：agent 问了同事，但没有接着处理对方的回答）
- 输出："找人"相关失败在所有失败中占多大比例，以及各模型分别在哪类找人错误上出问题。
- 先用 LLM 预标注，再人工抽检，并报告一致性 κ。

## 4. 一个需要你确认的取舍
"实证 + 设计框架"偏 HCI 包装（CHI/CSCW）；"训练一个模型"偏 NLP/ML 包装（ACL/EMNLP）。**两者都写进同一篇论文是可以的**，ReHAC 本身就是 NLP 论文，带一个真人实验。但不同的投稿目标，侧重点要不一样：

| 版本 | 内容 | 目标 venue | 时间 |
|---|---|---|---|
| **v1 workshop 版** | C1 框架 + §3 诊断 + C3 的零样本 LLM 对比（不训练模型） | **AAAI-27 Human-AI Collaboration workshop（11-20 截稿）** | 约 4 周，可行 |
| **v2 完整版** | 加上 C2 训练模型 + WhoBench + 完整的权重扫描 | ACL/EMNLP 2027（ARR），或 NeurIPS D&B | 约 3–5 个月 |
| **v2′ HCI 版**（可选） | 加一个小规模真人实验（真人扮演角色，或真人判断 agent 有没有找对人） | CHI 2028 / CSCW | 更长 |

**我的建议**：按 v1 → v2 推进。4 周内训练出一个好模型风险很高，而零样本 LLM 对比本身就能撑起一篇 workshop 论文。

## 6. 已知风险
- **新颖性**：多用户 agent 方向（Multi-User LLM Agents、Harness-MU）2026 年很活跃，要尽早占位，并在相关工作中明确区分：它们研究**被动地听谁的**，我们研究**主动地找谁**。
- **模拟的真实性**：NPC 由 LLM 扮演，打扰成本是人为设定的。缓解办法：成本做敏感性分析（在 C3 的权重扫描中顺带完成）；动机案例用你观察到的企业场景（需脱敏，并确认公司的发表政策）。
- **TheAgentCompany 许可证**：主仓库和 experiments 仓库的许可证都还没有确认。如果要发布衍生数据集，需要先确认。
- **评测器偏差**：如果用 LLM 判断"有没有问对人"，需要有人工抽检。
