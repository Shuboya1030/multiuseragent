研究问题、假设与实验设计（Who-to-Ask）v0.1

配套文件：who_to_ask_proposal.md（中文方案）、proposal_who_to_ask_EN.md（发给合作者的英文 proposal）。 标注 [v1] 的部分是 11-20 workshop 版要完成的；[v2] 是后续完整版。 本文中所有”预期结果”都是假设，不是已有发现。

0. 总体逻辑

论文要回答三层问题，每层对应一个贡献：

层次 问题 对应贡献
现象 现有 agent 在”找人”上会不会犯错？犯什么样的错？ 实证诊断
机制 给 agent 显式的角色信息能不能改善？它会不会根据成本和权限调整找人的行为？ 设计框架 + LLM 对比
方法 能不能学出一个比 prompt 更好的”何时 + 找谁”策略？ 训练模型 [v2]

1. 研究问题与假设

RQ1（现象）：当前 LLM agent 的求助失败有多常见、属于哪些类型？

  • H1a：在需要向同事获取信息的任务中，相当一部分失败与求助行为有关，包括问错人、该问没问、问了没跟进。（我们不预设具体比例，由数据决定。）
  • H1b：不同模型的求助错误类型分布不同。例如，有的模型更倾向于”不问而是自己编”，有的模型更倾向于”问了没跟进”。
  • H1c：求助失败与任务失败显著相关：发生求助错误的轨迹，检查点得分更低。

RQ2（框架）：显式的角色信息是否改善”找谁”？

  • H2a：提供的角色信息越结构化，首次求助命中率越高。三档条件分别为 R0（只有名字）、R1（自然语言职责描述）、R2（结构化角色档案）。预期 R2 > R1 > R0。
  • H2b：角色信息的收益主要体现在存在干扰候选人的任务上；只有一个正确候选人的任务里，三档条件差异很小。
  • H2c：结构化档案能减少越权求助（找了没有权限的人去批准事情），而不只是提高找对知识持有者的概率。

RQ3（成本敏感性）：agent 会不会根据打扰成本和权限约束调整找人行为？

  • H3a：提高打扰成本权重 λ（或者在 prompt 中说明某人”很忙、很贵”）时，理性的 agent 应该减少求助次数，并转向成本更低、但仍然有能力回答的候选人。我们预期部分 LLM 对成本不敏感，即行为几乎不随 λ 变化。
  • H3b：在”知情的人很贵、便宜的人只知道一部分”这类权衡情境中，LLM 的选择会偏离最优策略（最优策略由环境设计者事先算出）。
  • H3c：增加越权惩罚 μ 的说明后，越权次数下降，但可能以更多的”该问没问”为代价，也就是变得过度保守。

RQ4（方法）[v2]：学出来的策略是否优于 prompt 策略？

  • H4a：用离线 RL 训练的 7–8B 策略，在综合回报 R 上优于零样本 prompt 的大模型（对照 ReHAC 的结论）。
  • H4b：同时决定”何时问”和”问谁”的联合策略，优于两阶段策略（先由模型决定何时问，再用 prompt 决定问谁）。
  • H4c：训练好的策略在未见过的组织结构（不同的角色组合）上仍然有效，即泛化能力。

2. 实验设计

实验 1：轨迹诊断（检验 H1）[v1]

  • 数据：TheAgentCompany/experiments 中公开的轨迹。只保留 41 个带 scenarios.json 的任务，即需要找 NPC 的任务。12 组模型配置 × 41 个任务，最多约 490 条轨迹（实际数量需要核对）。
  • 标注单元：每一次 agent 向 NPC 发消息算一个”求助事件”。另外，对每个任务，把应该问却从未问过的人记作”漏问事件”。
  • 标签体系： | 标签 | 定义（依据 scenarios.json 中谁持有哪条信息） | |—|—| | Correct | 问了持有所需信息或权限的人，并且使用了对方的回答 | | Wrong-person | 问的人不持有所需信息或权限 | | Missed | 应该问而没有问（例如直接编造了答案或跳过了步骤） | | No follow-up | 问对了人，但没有使用或没有等待对方的回答 | | Redundant | 已经拿到答案后又重复询问 |
  • 流程：先用 LLM（例如 GPT-4.1）预标注，再随机抽 20% 由两人独立标注，报告 Cohen’s κ。如果 κ < 0.6，就修订标签定义后重新标注。
  • 分析：
    • H1a：报告各类标签的频数和比例，以及在失败任务中求助相关错误所占比例。
    • H1b：画模型 × 错误类型的列联表，做卡方检验。
    • H1c：做逻辑回归或混合效应模型。因变量为任务是否成功（或检查点得分）；自变量为是否出现求助错误；随机效应为任务和模型。
  • 工作量（估计）：几百条轨迹，LLM 预标注的 API 费用很低；人工抽检约 1–2 天。

实验 2：角色信息消融（检验 H2）[v1]

  • 环境：纯文本模拟器。任务改写自 TheAgentCompany 的 NPC 任务，NPC 由 LLM 扮演，按 scenarios.json 加上我们补充的私有信息作答。
  • 任务改造：每个任务设置 4–6 个候选人，其中只有 1 个是最优目标，其余是干扰项：
    • D1：知情但没有权限
    • D2：有权限但不知情
    • D3：知情且有权限，但打扰成本高
    • D4：只知道部分信息
    • 另外保留一组没有干扰项的对照任务，用于检验 H2b。
  • 自变量：
    • 角色信息条件：R0 / R1 / R2，被试内设计（同一任务在三种条件下各跑一次）
    • 被测模型：3–5 个（GPT、Claude、Gemini、Qwen、Llama）
  • 因变量：首次求助命中率、任务成功率、越权次数、求助轮数、总打扰成本。
  • 规模：约 50 个任务 × 3 种条件 × 4 个模型 × 每个配置 3 次重复 = 1,800 局。每局约 10–20 次 API 调用（估计）。
  • 分析：
    • H2a：广义线性混合模型，比如 hit ~ condition * model + (1|task)，做 R0 vs R1 vs R2 的事后对比，并报告效应量。
    • H2b：加入 condition × has_distractor 交互项。
    • H2c：以越权次数为因变量，做泊松或负二项回归。

实验 3：成本与权限权重扫描（检验 H3）[v1 部分完成，v2 完整做]

  • 操纵方式：在系统提示中告诉 agent 每个人的打扰成本，以及越权的后果。
    • λ ∈ {0, 低, 中, 高}，具体表现为每个候选人的成本数值；
    • 成本结构 ∈ {均匀, 按职级递增}；
    • μ ∈ {无提示, 明确禁止越权}。
  • 最优基线：环境设计者已知每个人掌握的信息和成本，可以事先算出在给定 λ 和 μ 下的最优求助策略及其期望回报，作为 oracle。
  • 因变量：求助次数、对高成本候选人的选择比例、相对 oracle 的回报差距（regret）、越权次数、漏问次数。
  • 分析：
    • H3a：画”λ → 求助次数”的剂量-反应曲线，用斜率衡量模型对成本的敏感度。
    • H3b：报告各模型在权衡类任务上的 regret 分布。
    • H3c：画 μ 操纵前后越权次数与漏问次数的变化，即权衡曲线。
  • 产出图：每个模型一条”任务成功率 vs 总打扰成本”的帕累托曲线。

实验 4：学习型策略 [v2]

  • 数据收集：参照 ReHAC，每一步以概率 p 让 agent 自己做，以 1−p 随机挑一个候选人询问，执行到底并记录回报。目标是数千条轨迹。
  • 模型：Qwen2.5-7B 或 Llama-3.1-8B + LoRA，输出 SELF 或 ASK(hᵢ)。
  • 训练：离线 REINFORCE 或 GRPO，λ 和 μ 作为条件输入，这样一个模型可以适配不同的成本设定。
  • 基线：
    1. agent 从不求助
    2. 随机求助
    3. 零样本 prompt（实验 2 中最好的 LLM + R2 条件）
    4. ReHAC 式两阶段策略（模型只决定何时问，问谁由 prompt 决定）
    5. 改编版多专家 L2D（每一步看作一次分类）
    6. oracle 上界
  • 泛化测试（H4c）：训练和测试使用不同的组织结构，比如换一批角色、换一套职级成本。

3. 效度与威胁

威胁 说明 缓解办法
NPC 不真实 LLM 扮演的同事可能过于配合或过于一致 NPC 的回答严格由脚本约束（只能透露 scenarios.json 规定的信息）；抽样做人工检查；v3 阶段加入真人扮演
成本是人为设定的 打扰成本没有真实依据 不只报告某一个成本点的结果，而是做成本扫描（实验 3），看结论在不同成本下是否稳健
评测器偏差 用 LLM 判断问没问对人可能出错 实验 2 和 3 用规则评测，因为每个任务的正确目标人事先已经标好；只有实验 1 依赖 LLM 标注，再加人工抽检
数据泄露或污染 模型可能见过 TheAgentCompany 的数据 改写任务表述和人名，并加入新设计的干扰候选人
外部效度 模拟的是一家软件公司 在论文中声明限制；v2 用 EnterpriseBench 的组织元数据生成其他行业的组织
许可证 TheAgentCompany 的许可证未确认 只发布我们自己改写的任务和标注，并先与原作者确认

4. Workshop 版本（11-20）的最小可交付范围

  • 实验 1：完整完成。
  • 实验 2：约 30–50 个任务，3 个模型（例如 GPT-4.1、Claude Sonnet、一个开源模型）。
  • 实验 3：只做 λ 扫描的剂量-反应曲线。
  • 论文结构：问题与框架 → 实验 1 的诊断发现 → 实验 2 和 3 的对比结果 → 讨论与 v2 计划。正文约 4–6 页。

5. 待合作者讨论的开放问题

  1. 角色档案的五个维度（知识、权限、成本、可用性、可信度）是否完整？要不要加”关系或信任”维度，或者”响应延迟”？
  2. 在 R2 条件里，权限要怎么表示：用访问控制规则（RBAC 风格），还是用自然语言描述？
  3. 真人实验做哪个方向：真人扮演 NPC（提高生态效度），还是真人判断 agent 有没有找对人（建立人类基线）？
  4. 最终投 HCI 方向（CHI/CSCW）还是 NLP 方向（ACL/EMNLP）？这决定 v2 的重点放在哪里。
